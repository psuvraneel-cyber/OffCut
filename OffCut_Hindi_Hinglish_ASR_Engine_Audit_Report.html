1. Executive Assessment

OffCut's browser-based Hindi and Hinglish transcription pipeline is technically unsound, unreliable, and completely unsuitable for production use. While the repository contains recent commits intended to mitigate corrupted Unicode output, repetition loops, and Persian-Arabic script leakage, live empirical evaluation confirms that the engine remains essentially non-functional on real-world spoken Hindi and Hinglish.

Direct Answers to Fundamental Questions

  1. Is the Hindi transcription capability reliable, usable, and production-ready?
    No. Standard conversational Hindi speech achieves 100% to 150% WER. Whisper tiny translates Hindi speech into hallucinated English sentences, while Whisper base outputs Urdu Perso-Arabic tokens that are 100% purged by the script filter, leaving empty transcripts.
  2. Is the Hinglish transcription capability reliable, usable, and production-ready?
    No. Spoken Hinglish exhibits a 94.88% WER and 68.93% deletion rate. On long conversational dialogue, deletion reaches 99.15% (116 of 117 words dropped), yielding a single hallucinated word.
  3. Did recent commits fix the underlying problems?
    No. The changes added heuristic filters (blocking Arabic script, regex dictionary mapping) without fixing the tokenizer, decoding, audio conditioning, or evaluation flaws.
  4. What are the 3 largest architectural blockers?
    • Benchmark Reference Script Mismatch: UI promises Romanized Hinglish, but ground truth references are 85% Devanagari. The scoring harness performs raw string comparisons, guaranteeing ~95% WER.
    • Window-Level Language Forcing for Code-Switching: Per-window language detection forces Whisper into either en or hi, destroying intra-sentential code-switching.
    • Destructive Per-Window Peak Normalization: Audio conditioning amplifies low-amplitude windows by up to +45 dB, elevating background noise and causing hallucination loops.

2. Repository & Implementation Summary

OffCut executes speech-to-text locally inside a Web Worker (engine/src/whisper/worker.ts) using Hugging Face Transformers.js and ONNX Runtime Web.

  • Pass 1: Silero VAD & Windowing: Runs across PCM audio in 30-second blocks, producing probability curves to identify speech boundaries and group them into speech-bounded windows (≤ 30s).
  • Pass 2: Language Routing & Whisper Decoding:
    • In hinglish mode: Probes RMS and runs per-window language detection, forcing either hi or en.
    • In auto mode: Probes window 0 and re-detects language on subsequent loud windows.
    • Passes audio window to speechPipeline(audio, { language, task: "transcribe", max_new_tokens }).
  • Pass 3: Post-Processing & Filtering:
    • Filters illegal Unicode scripts via filterForeignScriptWords().
    • Removes repetition loops and junk words.
    • If hinglish is selected, executes rule-based transliteration from Devanagari to Roman script.

Key Component Findings

1. The Destructive Audio Normalization Flaw (PIPE-001)

In engine/src/audio/decode.ts (line 137), conditionAudio() is executed on every window slice independently. In engine/src/audio/dsp.ts (line 60), normalizePeak uses minPeakForNormalization = 0.001 (-60 dBFS). When an audio window contains quiet speech or silence with peak amplitude 0.005 (-46 dBFS), it is multiplied by 0.95 / 0.005 = 190.0 (+45.6 dB of artificial gain). This obliterates the natural dynamic range across windows, elevating background air-conditioning hiss and room acoustics into loud noise that triggers Whisper hallucinations.

2. Transliteration Mangles English Loanwords (HNG-002, HNG-003)

When Whisper transcribes Hinglish speech in Devanagari, it writes English loanwords phonetically (e.g. प्रॉपगैंडा, एक्चुअली, प्रॉब्लम). transliterateDevanagariToHinglish() mechanically transliterates these Devanagari characters:

  • एक्चुअली → "ekchualee" (Expected: actually)
  • प्रॉपगैंडा → "praॉpagainda" (Broken Candra matra + phonetic distortion)
  • प्रॉब्लम → "praॉblam" (Broken Candra matra)

Furthermore, engine/test/transliterate.test.ts passed 100% only because all 20 test words were manually entered into the 180-word COLLOQUIAL_MAP. Unmapped Hindi words lack medial schwa deletion (e.g. चमकना becomes "chamakanaa").

7. Benchmark Methodology & Dataset Quality (BENCH-001)

The evaluation methodology suffers from a critical structural contradiction:

  • UI Specification: In CaptionsPage.tsx, Hinglish is defined as "Bilingual Indian speech mixing Hindi and English, outputted in Roman script."
  • Dataset Ground Truth: In asr-evaluation-assets/03_hinglish, reference transcripts are written in 84.7% Devanagari script.
  • Scoring Harness: engine/bench/wer.ts performs raw string token equality (ri === h[j - 1]). Comparing Romanized token "hain" against Devanagari token "हैं" counts as a 100% substitution error.

Consequence: An ASR engine providing perfectly accurate Romanized Hinglish captions is mathematically guaranteed to receive an ~85% to 100% WER in the benchmark harness.

9. Prioritized Remediation Roadmap

Phase P0: Critical Infrastructure Fixes (Immediate)

  • P0.1: Script-Aware Scoring Normalization: Update engine/bench/wer.ts to normalize both hypothesis and reference into Roman script for Hinglish evaluation.
  • P0.2: Benchmark Harness Hinglish Queue: Update engine/bench/main.ts to evaluate language: "hinglish" mode.
  • P0.3: Global Audio RMS Normalization: In decode.ts, replace per-window peak normalization with track-level global RMS normalization.
  • P0.4: Urdu-to-Devanagari Transliteration: Convert Perso-Arabic tokens into Devanagari rather than deleting them when language: "hi" is selected.

Phase P1: Code-Switching & Transliteration Overhaul

  • P1.1: Default Hinglish Prompt Conditioning: Inject a bilingual prompt (e.g. "Main kal market gaya tha to buy some groceries") into pipelineOptions.initial_prompt to condition Whisper for code-switching.
  • P1.2: Add Missing Candra Matras: Add ॉ: "o" and ॅ: "e" to MATRAS in transliterate.ts.
  • P1.3: Syllabic Schwa Deletion: Implement standard Hindi foot-based schwa deletion in unstressed syllables.
  • P1.4: English Lexicon Lookup: Map phonetic Devanagari representations of common English words (प्रॉपगैंडा, बिलीव) directly back to English words (propaganda, believe).

Phase P2: VAD & Retry Hardening

  • P2.1: Speech-Aware Retry Slicing: Align bisection retries to Silero VAD silence gaps rather than slicing words at the 50% midpoint.
  • P2.2: Temperature Fallback Schedule: Implement fallback temperatures [0.0, 0.2, 0.4] before attempting window splitting.

Phase P3: UI Transparency & Indic Models

  • P3.1: Remove False Claims: Remove the unverified "3x higher accuracy on Small Model" claim from CaptionsPage.tsx.
  • P3.2: Indic-Fine-Tuned ONNX Models: Evaluate community Indic-specialized fine-tuned Whisper ONNX checkpoints (e.g. IndicWhisper).
